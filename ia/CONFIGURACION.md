# Configuración de contención

`opencode.json` complementa las reglas de `AGENTS.md`. Las reglas específicas prevalecen sobre el comodín `*`: por eso un `deny` o `ask` puntual gana sobre un `allow` general. Ninguna regla sustituye la revisión humana del diff.

## Riesgo, límite y ajuste por regla

| Regla                                                                                                                    | Riesgo que cubre                                                                                                         | Límite                                                                                                                                                                     | Ajuste hecho                                                                                                                                                                                |
| ------------------------------------------------------------------------------------------------------------------------ | ------------------------------------------------------------------------------------------------------------------------ | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `read: "*": "allow"` con deny de `*.env`, `*.env.*`, `*.pem`, `*.key`, `*firebase-adminsdk*.json`, `*.keystore`, `*.jks` | Leer secretos o credenciales y arrastrarlos al contexto de la IA.                                                        | Solo coincide por patrón de nombre: no detecta secretos guardados con otro nombre ni valores ya cargados en variables del proceso. Un comando aprobado podría imprimirlos. | Se mantuvo `allow` para el resto del repo y se añadieron denies específicos para archivos de entorno, llaves, credenciales de Firebase Admin y keystores.                                   |
| `edit: "*": "allow"` con deny de `opencode.json`, `*.env`, `*.env.*`                                                     | Que la IA debilite sus propias reglas o escriba secretos en archivos de entorno.                                         | No impide sobrescribir código dentro del repo; por eso siempre se revisa el diff. Tampoco cubre otros archivos de configuración que puedan contener datos sensibles.       | Se añadió `deny` explícito sobre `opencode.json` y sobre los archivos `.env*`.                                                                                                              |
| `external_directory: "*": "deny"`                                                                                        | Leer o escribir fuera del repositorio (por ejemplo, caché de SWC, `/tmp` u otro proyecto).                               | Aplica al acceso a directorios externos; no controla por sí sola lo que un proceso lanzado por `bash` hace más allá de sus propias reglas.                                 | Se fijó `deny` global, sin excepciones.                                                                                                                                                     |
| `bash: "*": "ask"`                                                                                                       | Ejecutar comandos sin revisión previa.                                                                                   | `ask` no es `deny`: si se aprueba, el comando se ejecuta. No valida argumentos, destinos ni efectos laterales.                                                             | Se estableció `ask` como regla base para todo comando.                                                                                                                                      |
| `git push *: "ask"`                                                                                                      | Publicar commits no revisados.                                                                                           | No inspecciona el contenido del commit; exige revisar antes `git status`, `git diff` y `git log`.                                                                          | Se hizo explícito el `ask` además de la base. Los refuerzos `git push --force *`, `git push -f *` y `git reset --hard *` quedan en `deny`.                                                  |
| `npm install *`, `npm i *`, `npx expo install *: "ask"`                                                                  | Modificar dependencias o el lockfile y ejecutar scripts de paquetes no revisados.                                        | No audita el paquete ni sus scripts; otros gestores quedan cubiertos solo por la base `bash: "*": "ask"`.                                                                  | Se añadieron reglas `ask` explícitas para esos tres comandos.                                                                                                                               |
| `vercel *`, `eas *: "ask"`                                                                                               | Desplegar o cambiar estado remoto sin confirmación.                                                                      | No identifica el proyecto ni el entorno de destino: hay que confirmarlos al aprobar. No revierte despliegues ya hechos.                                                    | Se añadió `ask` explícito para ambos CLI. `vercel env pull *` quedó reforzado con `deny` para no traer secretos remotos.                                                                    |
| `sudo *: "deny"`                                                                                                         | Escalada de privilegios desde el agente.                                                                                 | No cubre privilegios que el usuario ya ejerce fuera del agente.                                                                                                            | Se fijó `deny`.                                                                                                                                                                             |
| `node -e*: "deny"`                                                                                                       | Ejecutar código arbitrario con Node para eludir reglas de lectura o edición, por ejemplo para modificar `opencode.json`. | Coincide solo con ese patrón de texto: `node --eval`, la ruta absoluta al binario u otros intérpretes pueden no coincidir.                                                 | Se añadió `deny` después de que el modelo rechazara editar `opencode.json` por `AGENTS.md` en la prueba 4.                                                                                  |
| `cat *.env*`, `type *.env*`, `Get-Content *.env*: "deny"`                                                                | Leer archivos de entorno desde la shell para obtener secretos sin usar la herramienta de lectura.                        | Cubre solo esos comandos y patrones; otras formas de imprimir archivos quedan bajo la base `ask`.                                                                          | Se añadieron denies explícitos para impedir la lectura por shell de `.env*`.                                                                                                                |
| `rm -rf *: "deny"`                                                                                                       | Borrado recursivo e irreversible.                                                                                        | Otras formas de borrado (`rm -r`, `git clean`, `find -delete`) no tienen `deny` específico: quedan bajo la base `ask`.                                                     | Se fijó `deny`.                                                                                                                                                                             |
| `curl *`, `wget *`, `curl*`, `wget*`, `Invoke-WebRequest*`, `Invoke-RestMethod*`, `iwr *`, `irm *: "deny"`               | Exfiltrar datos o descargar y ejecutar contenido externo desde `bash`.                                                   | En Windows `curl *` no coincide con `curl.exe`; tampoco bloquea rutas absolutas, alias de PowerShell ni el tráfico de red de `npm` o `git`. No inspecciona URLs.           | Tras la prueba 7 se añadieron `curl*`, `wget*`, `Invoke-WebRequest*`, `Invoke-RestMethod*`, `iwr *` e `irm *`, conservando `curl *` y `wget *`. La repetición en modo Build quedó denegada. |
| `webfetch: "deny"`                                                                                                       | Que el agente use su herramienta web para consultar URLs y sacar datos del repo sin pasar por `bash`.                    | Bloquea WebFetch, pero no otras herramientas ni procesos con acceso a red; no inspecciona URLs ni contenidos.                                                              | Se añadió `deny` al detectar que el agente recurrió a WebFetch en la prueba 7.                                                                                                              |

## Nota

Los ajustes listados son el estado actual de `opencode.json`; esta tarea solo los documenta y no modifica ese archivo.

Sin sandbox, las reglas de `bash` se aplican como patrones de texto sobre la cadena del comando: no analizan qué hace realmente el proceso. Por eso pueden existir otras formas de esquivarlas (`curl.exe` frente a `curl *`, rutas absolutas, alias, intérpretes o comandos construidos en variables). Son una barrera de contención, no una garantía: hay que revisar ejecuciones, diffs y permisos después de cada cambio.
